# maga-safe · SafeNet KZ

Прототип для хакатона SafeNet KZ (Шымкент, 2026): поиск признаков незаконных схем в соцсетях и мессенджерах Казахстана.

- **Трек 1, «Розыгрыши под контролем»:** платные лотереи и розыгрыши.
- **Трек 2, «Скрытая игра»:** скрытая реклама онлайн-казино.
- **Трек 3, «Стоп-пирамида»:** финансовые пирамиды в WhatsApp/Telegram.

Система не выносит вердикт, а показывает **признаки** нарушения с цитатами и уровнем риска (низкий / средний / высокий), а решение принимает аналитик. Подробнее см. [docs/case.md](docs/case.md).

## ПРУФ: что внутри

Мошенники меняют слова, но переиспользуют «пруфы»: скрины выплат, голосовые, шаблоны текстов, номера Kaspi, домены. ПРУФ ищет признаки схем в каждом сообщении и связывает сообщения через общие пруфы и реквизиты в кейсы, на всех трёх треках сразу.

- **Детектор признаков** для текста, скриншотов (OCR), голосовых (Whisper, если подключён) и ссылок на ru, kk и транслите: правила с цитатами, ML-модель, Claude для спорных случаев. Риск низкий / средний / высокий, формулировки «найдены признаки».
- **Реестр ПРУФ**: почти-дубликаты изображений (PDQ + OCR), текстов (MinHash LSH), голосовых, ссылок и реквизитов. Дифф сумм и дат между копиями одного скрина, ELA в зоне цифр. Повтор сам по себе не риск.
- **Граф кейсов**: посты, каналы, реквизиты, пруфы и домены; кейсы, семейства кампаний, пакет доказательств ZIP с SHA-256 и временем UTC.
- **Дашборд аналитика**: обзор с динамикой и **ранними сигналами** (реквизит разошёлся по 3+ каналам за 72 часа), очередь кейсов с поиском и клавишами, интерактивный граф связей, пруфы по семействам, подсветка признаков прямо в тексте, отчёт по кейсу для печати и PDF.
- **Telegram-бот** (анонимный режим не раскрывает базу и не тратит LLM) и **API для банков** (лента засвеченных реквизитов и проверка номера, есть и в дашборде).
- **Синтетика и метрики**: генератор со связями между треками и легальными контрольными примерами, eval (precision / recall / FPR), слепые ручные наборы (пишет отдельный агент без доступа к коду; на свежем наборе v3 из 80 постов: precision 0,86, recall 0,75, FPR 0,125 против 0,69 / 0,45 / 0,20 у кода первого раунда), нагрузочный тест на 1 млн.

Документы: [архитектура](docs/architecture.md), [план](docs/plan.md), [метрики](docs/metrics.md), [план внедрения](docs/rollout.md).

## Запуск

Нужен Python 3.11+ (тесты проходят на 3.11, 3.12 и 3.13).

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt

# демо-данные: фон + «вау»-сценарий (один скрин выплаты, 37 появлений, 5 правок суммы,
# один номер Kaspi в розыгрыше, казино и пирамиде); модель обучится сама, если её нет
PRUF_DEV_MODE=1 PRUF_DATA_DIR=data/demo python scripts/seed_demo.py --reset

# сервер (строго один воркер: индексы в памяти процесса)
PRUF_DEV_MODE=1 PRUF_DATA_DIR=data/demo uvicorn pruf.api.app:create_app --factory --port 8000
```

Откройте http://localhost:8000. Демо-путь: «Обзор» → ранний сигнал по номеру +77473185264 → «Открыть кейс C-211» (три трека, 12 каналов) → граф связей (наведите на узел) → карточка «×37 копий» → таймлайн, флажок «только копии с правками»: суммы обведены красным. «Отчёт для печати» собирает кейс в документ. Вкладка «Проверить» с готовыми примерами (ru, kk, транслит, легальный), «Реквизиты» — лента для банка и проверка номера.

### Переменные окружения

| Переменная | Что задаёт |
|---|---|
| `PRUF_DATA_DIR` | каталог базы и файлов (по умолчанию `data/`) |
| `PRUF_DEV_MODE=1` | режим разработки: токены не обязательны, случайный HMAC-ключ. Не для прода |
| `PRUF_ANALYST_TOKEN` | токены аналитиков через запятую, формат `имя:токен` |
| `PRUF_BANK_TOKENS` | токены банков, формат `halyk:токен,...` |
| `PRUF_HMAC_KEY` | ключ сопоставления номеров карт (обязателен вне dev-режима) |
| `ANTHROPIC_API_KEY` | включает Claude для спорных случаев (`PRUF_LLM_MODEL`, по умолчанию `claude-opus-5-5`) |
| `TELEGRAM_BOT_TOKEN`, `PRUF_TELEGRAM_SECRET` | бот: токен и секрет вебхука |
| `PRUF_RESOLVE_LINKS=1` | раскрывать сокращённые ссылки (с защитой от внутренних адресов) |
| `PRUF_MAX_UPLOAD_BYTES`, `PRUF_RATE_LIMIT` | лимит файла (8 МБ) и запросов в минуту (120) |

### Telegram-бот

```bash
TELEGRAM_BOT_TOKEN=... PRUF_DATA_DIR=data/demo PRUF_DEV_MODE=1 python -m pruf.bot.telegram
```

Или вебхук: задайте `TELEGRAM_BOT_TOKEN` и `PRUF_TELEGRAM_SECRET` для сервера и зарегистрируйте `https://<хост>/api/v1/telegram/webhook` через `setWebhook` с `secret_token`. Бот ничего не сохраняет, только читает реестр: перешлите ему скрин из демо, и он ответит, что скрин уже встречался в постах с признаками схем и что суммы на копиях отличались. Каналы, суммы и счётчики из базы бот не раскрывает. Отвечает только в личных чатах; секрет вебхука не короче 32 символов.

### API

Все ответы в формате `{success, data, error, meta}`, токен в `Authorization: Bearer …`.

| Метод | Назначение |
|---|---|
| `POST /api/v1/analyze/text` | проверка текста (`store: false` ничего не сохраняет) |
| `POST /api/v1/analyze` | приём поста с файлами (multipart) |
| `GET /api/v1/cases`, `GET/PATCH /api/v1/cases/{key}` | очередь и карточка кейса, статус аналитика |
| `GET /api/v1/cases/{key}/export` | пакет доказательств ZIP |
| `GET /api/v1/artifacts/{id}/timeline` | все появления пруфа с диффом сумм и дат |
| `GET /api/v1/posts/{id}/related` | связанные посты |
| `GET /api/v1/bank/requisites`, `POST /api/v1/bank/check` | лента реквизитов и проверка номера для банка |
| `GET /api/v1/overview` | динамика по дням, треки, топ-каналы, статусы кейсов, ранние сигналы |
| `GET /api/v1/stats`, `GET /api/v1/health` | статистика, что работает, здоровье |

### Метрики, тесты, нагрузка

```bash
python scripts/gen_synthetic.py && python scripts/train.py   # синтетика и модель
python scripts/eval.py --mode both                           # docs/metrics.md, reports/eval.json
python scripts/loadtest.py --n 1000000                        # reports/loadtest.json
pytest --cov=pruf                                             # тесты и покрытие (E2E в Chromium, если есть Playwright)
```
