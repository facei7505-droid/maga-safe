# Пилот ПРУФ с банком

Одна страница для отдела антифрода и шаблон письма о намерениях. Цель пилота — проверить на живых переводах,
что реквизиты из ленты ПРУФ чаще оказываются мошенническими, чем случайные, и что банк узнаёт о них раньше
первых жалоб клиентов.

## Что получает банк

| Что | Как | Зачем |
|---|---|---|
| Лента засвеченных реквизитов | `GET /api/v1/bank/requisites?since=…&list=black` или CSV | Подгрузить в правила антифрода: перевод на номер из ленты — повод для паузы или подтверждения |
| Проверка одного реквизита | `POST /api/v1/bank/check` | Оператор или правило проверяет получателя перед переводом; значение не сохраняется |
| Исходы других банков | поле `bank_outcomes` в ответе проверки | «Два банка подтвердили мошенничество» — без названий банков |
| Обезличенный обмен | CSV с HMAC-ссылками ключом обмена (`export_ref`) | Сверить со своими получателями, не раскрывая номеров друг другу |

Что банк отдаёт обратно: `POST /api/v1/bank/feedback` с исходом `fraud_confirmed` (перевод оказался мошенничеством)
или `legit_client` (это наш честный клиент). Это самый весомый сигнал для аналитика ПРУФ; список и оценку он сам
не меняет. Хранятся маскированный реквизит и дата, без имён и сумм.

## Интеграция за один день

```bash
# проверка получателя
curl -s -X POST https://<сервер>/api/v1/bank/check -H "Authorization: Bearer $BANK_TOKEN" \
     -H "Content-Type: application/json" -d '{"value": "+7 747 318 52 64"}'
# → {"success": true, "data": {"found": true, "list": "black", "posts": 37, "tracks": [...],
#     "bank_outcomes": {"fraud_confirmed": 2, "legit_client": 0}, "advice": "…"}}

# новые засвеченные реквизиты с прошлой выгрузки
curl -s "https://<сервер>/api/v1/bank/requisites?since=2026-11-01&min_level=high" -H "Authorization: Bearer $BANK_TOKEN"

# исход после разбора инцидента
curl -s -X POST https://<сервер>/api/v1/bank/feedback -H "Authorization: Bearer $BANK_TOKEN" \
     -H "Content-Type: application/json" -d '{"value": "+7 747 318 52 64", "outcome": "fraud_confirmed"}'
```

Токен банка: `PRUF_BANK_TOKENS=halyk:<токен>`; лимит запросов на токен, перебор токенов ограничен по IP,
каждый запрос в журнале аудита. Ответы в едином формате `{success, data, error, meta}`.

## Приватность

- ПРУФ обрабатывает только открытые публикации и то, что люди сами прислали боту или отметили в расширении.
- Номера карт маскируются до записи, для сопоставления хранится HMAC; ключ обмена выводится из ключа сервера и не раскрывает его.
- Проверка реквизита банком ничего не сохраняет; исход хранится маскированным, с датой без времени.
- Правовая рамка для согласования с юристами банка — docs/rollout.md, «Кому и зачем».

## Метрики пилота (8 недель)

| Метрика | Как считаем | Цель |
|---|---|---|
| Доля мошеннических среди реквизитов ленты | исходы `fraud_confirmed` / все исходы по реквизитам ленты | заметно выше базовой доли мошенничества среди получателей банка |
| Опережение | дата появления в ленте против даты первой жалобы клиента в банк | лента раньше жалобы в большинстве случаев |
| Ложные остановки | `legit_client` по реквизитам из чёрного списка | единицы; каждый случай — разбор правила |
| Нагрузка | проверок в день, время ответа p95 | без деградации платёжного потока |
