# ПРУФ: полный анализ проекта

Состояние на 26.10.2026, ветка main. Цифры ниже посчитаны по коду и тестам этого коммита; метрики качества
взяты из `docs/metrics.md` и замеров на реальных постах.

## 1. Что это и для кого

ПРУФ находит в открытых каналах Казахстана три вида финансового мошенничества: платные и фальшивые розыгрыши,
скрытую рекламу онлайн-казино и финансовые пирамиды. Главная идея — мошенники меняют слова, но годами повторяют
одни и те же «пруфы»: скрин выплаты, номер Kaspi, домен, QR-код. Система ищет признаки схемы в каждом посте,
связывает посты через общие пруфы в кейсы и отдаёт результат четырём адресатам:

| Кто | Что получает | Через что |
|---|---|---|
| Аналитик (АРРФР, полиция) | Очередь кейсов с приоритетом, граф сети, пакет доказательств | Дашборд `web/`, API |
| Банк | Серый, чёрный и «снятый» списки реквизитов, проверка номера, обмен исходами | Банковское API |
| Гражданин | Риск поста или скрина за секунды | Telegram-бот, расширение Sentinel |
| Сама система | Новые каналы схем | Агент-разведчик |

Принцип, который держится во всём коде: система показывает **признаки с цитатами**, решение принимает человек.

## 3. Как устроено

```
Источник ─► Нормализация ─► Детектор ─► Реестр пруфов ─► Граф и кейсы ─► Выдача
бот, API,   текст, OCR, QR,  правила +    PDQ, MinHash,    сети, Louvain,   дашборд, бот,
расширение, ссылки,          ML +         SHA-256          ключевой         расширение,
разведчик   реквизиты        Claude                        реквизит         API банка
```

Один процесс на Python: FastAPI, а внутри весь конвейер (`pruf/pipeline.py`). Рабочая база — SQLite; решения
людей дополнительно сохраняются снимком в Postgres (`pruf/storage/state.py`), чтобы пережить перезапуск.

### Модули

| Модуль | Что делает | Как |
|---|---|---|
| `normalize/` | Приводит всё к одному виду | Гомоглифы и leet (к@зино → казино), транслит, казахские буквы; OCR (RapidOCR); QR (OpenCV); канонизация и раскрытие коротких ссылок с защитой от внутренних адресов; телефоны, карты (Луна), IBAN, Kaspi Pay |
| `detect/` | Находит признаки | Регулярные выражения с цитатами (`lexicon.py`, `rules.py`); ML: TF-IDF по символьным 2–5-граммам + логистическая регрессия; Claude только в спорной зоне, цитаты которого сверяются с текстом |
| `scoring.py` | Считает балл 0–100 и уровень | Сумма весов с насыщением; потолки: один признак — не выше 34, «высокий» только при сочетании, предупреждение и новость снижают |
| `registry/` | Узнаёт повторы | PDQ-хеш картинок (перебор по Хэммингу), MinHash LSH для текстов, OCR-дифф сумм и дат между копиями, ELA |
| `graph/` | Собирает кейсы и сети | Компоненты связности рискованных постов, сообщества Louvain, ключевой реквизит (чья блокировка отрезает больше каналов), ротация номеров |
| `lists.py` | Списки для банков | Серый → чёрный (кейс подтверждён) или «снят» (отклонён); HMAC для обмена без раскрытия номеров |
| `bot/` | Бот для граждан | Ответ на ru/kk, кнопка «Это не мошенничество», анонимный режим не раскрывает базу |
| `scout/` | Разведчик | Идёт от известных каналов по ссылкам, репостам и общим реквизитам; только читает |
| `api/` | REST | Роли (аналитик, банк, расширение), лимиты, проверка загрузок, вебхук бота |
| `storage/` | Хранение | SQLite, файлы по SHA-256, снимок решений людей в Postgres |
| `audit.py`, `feedback_training.py`, `prod_model.py` | Качество данных и модели | Слепая проверка разметки экспертом, дообучение на решениях аналитика с проверкой «чемпион и претендент», модель для прода с манифестом |
| `extension/` | Расширение Chrome | Плашка в Telegram Web, WhatsApp Web, Instagram; стоп на копировании засвеченного номера; текст поста не уходит из браузера |

## 4. Качество

| Свежие реальные посты (не виденные системой каналы) | Precision | Recall | Ложные тревоги |
|---|---|---|---|
| real_v4, модель обучена с реальными постами real_v1–v3 | 0,92 | 0,83 | 3,1% |
| real_v4, модель без реальных постов | 0,86 | 0,77 | 5,5% |
| real_v4, только правила | 0,90 | 0,56 | 2,7% |
| real_v3, модель без реальных постов | 0,88 | 0,57 | 4,0% |

- На сервере модель, обученная на всех 1 639 реальных постах (real_v1–v4); её собственного беспристрастного
  замера пока нет — нужен следующий свежий набор real_v5.
- Полнота на свежих реальных наборах растёт от раунда к раунду: 0,48 → 0,57 → 0,77 → 0,83.
- Правила дают высокую точность (0,90), но ловят около половины; модель добирает полноту. Claude в спорной зоне
  на рукописном наборе v10 поднимал полноту с 0,78 до 0,87.
- Слабые места по трекам: пирамиды и казахский язык.

## 5. Сильные стороны

1. **Объяснимость.** Каждое срабатывание — с дословной цитатой; Claude не может «придумать» улику.
2. **Пруфы и граф, а не только слова.** Повтор скрина, общий номер или QR связывают посты разных каналов и площадок
   в один кейс; ключевой реквизит говорит банку, что блокировать первым.
3. **Честная методика.** Каждый раунд меряется на свежем слепом наборе один раз; реальные наборы — 24 новых канала,
   два независимых разметчика, каппа 0,91–0,98. В README цифры по реальным постам идут первыми.
4. **Защита от ложных обвинений.** Обязательные сочетания для высокого риска, стоп-признаки легальности, распознавание
   предупреждений, новостей, рассказов пострадавших; маскировка («осторожно, фейки — переводите сюда») не проходит.
5. **Приватность по умолчанию.** Карты маскируются до записи, сопоставление по HMAC, расширение не отправляет текст,
   бот не раскрывает базу, у расширения доступ только к мессенджерам.
6. **Инженерия.** 95% покрытия, CI на трёх версиях Python с Postgres, e2e в браузере, тест на линейное время всех
   регулярных выражений, деградация видна (OCR, Whisper, LLM недоступны — это показано, а не скрыто).
7. **Петля обучения.** Решения аналитика, споры из бота и исходы банков становятся разметкой; модель меняется только
   через ворота «не хуже прежней».

## 6. Слабые стороны и риски

| Риск | Насколько серьёзно | Что с этим |
|---|---|---|
| Пропускается около каждой шестой схемы на свежих каналах, больше всего пирамид и казахского | Высоко | Следующий раунд на real_v5; Claude-арбитр на сервере (нужен ключ) |
| Разметка ИИ, без эксперта-человека | Средне | `scripts/human_audit.py` готов; нужен эксперт партнёра |
| Охват: сбор только публичного Telegram | Средне | Закрытые чаты — через пересылки боту и расширение (`docs/coverage.md`); Instagram — через официальный доступ Meta |
| Бесплатный Render: засыпает, 512 МБ, OCR и Whisper выключены, бесплатный Postgres ограничен по сроку | Средне для демо, высоко для пилота | Разогрев `scripts/warmup.py`; для пилота план standard (2 ГБ) и постоянный Postgres |
| Один процесс, индексы в памяти, SQLite | Низко для пилота в регионе, высоко для страны | План в `docs/architecture.md`: Postgres, очередь для OCR, Neo4j, FAISS |
| Словарь — сотни регулярных выражений | Средне | Защищён тестами (ReDoS, ложные тревоги, полнота); поддерживать сложно |
| Нет внешнего подтверждения (банк, регулятор) | Средне | `docs/pilot/bank.md`: API в обе стороны и шаблон письма |
| Правовая оценка не сделана | Средне | Нужен юрист: персональные данные, обработка открытых публикаций |

## 7. Что сделать дальше (по пользе)

1. **Свежий набор real_v5** (24 новых канала) — честная цифра для модели на сервере и проверка правок по пирамидам
   и казахскому.
2. **Ключ Claude на Render** — плюс 9 пунктов полноты в спорной зоне при бюджете 50 вызовов в сутки.
3. **Эксперт-человек** размечает 120 постов через `human_audit.py` — ответ жюри «кто решил, что это мошенничество».
4. **Письмо банка о намерениях** по шаблону `docs/pilot/bank.md`.
5. **План standard на Render** перед пилотом: OCR сумм на скриншотах и постоянный Postgres.

## 8. Деплой и репозиторий

- Docker-образ на Render по `render.yaml`: при сборке ставится модель из `models/prod`, если сходятся хэш и версия
  scikit-learn; демо-данные создаются при старте; решения людей восстанавливаются из Postgres `pruf-state`.
- После изменения `render.yaml` (добавлена база) Blueprint нужно один раз синхронизировать в панели Render.
- Ветки, из которых собирался Render (`claude/pruf-win`, `claude/project-thread-l88132`), перемотаны до main.
- CI: `.github/workflows/tests.yml` на каждый push; `warmup.yml` вручную перед питчем.
