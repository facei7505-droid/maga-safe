# ПРУФ: план реализации

Формат `/plan` из ECC. Подтверждение получено от maga («если всё есть, начинай собирать»).

## Требования

1. Детектор признаков для текстов, скриншотов, голосовых и ссылок на ru, kk и транслите; риск низкий/средний/высокий с цитатами; формулировки «найдены признаки».
2. Реестр ПРУФ: поиск почти-дубликатов изображений, текстов, голоса, ссылок и реквизитов Kaspi; дифф сумм/дат между копиями; признаки правки.
3. Граф кейсов, семейства кампаний, экспорт пакета доказательств.
4. Дашборд аналитика, Telegram-бот, API для банков.
5. Синтетический датасет со сквозными связями между треками и легальными контрольными примерами; eval с precision/recall/FPR; нагрузочный тест индекса на ~1 млн.

## Допущения

- Внешние API разрешены, но всё работает и без них (LLM, эмбеддинги, Whisper подключаемые).
- Тестовые данные жюри могут быть только текстовыми или с изображениями: eval поддерживает оба режима.
- Python 3.12+, FastAPI, SQLite для MVP.

## Этапы

| # | Этап | Результат | Сложность |
|---|---|---|---|
| 1 | Нормализация и детектор | `pruf/normalize`, `pruf/detect`, тесты на ru/kk/транслит и легальные примеры | средняя |
| 2 | Реестр ПРУФ | PDQ + MIH, MinHash LSH, реквизиты, OCR-дифф, ELA, тесты | высокая |
| 3 | Хранилище, пайплайн, граф, скоринг | приём Submission → кейс; экспорт ZIP | средняя |
| 4 | API и дашборд | очередь, карточка, дифф, таймлайн, «найти связанные» | средняя |
| 5 | Синтетика и метрики | генератор, eval, нагрузочный тест, демо-сид «37 появлений» | средняя |
| 6 | Бот и банковский API | Telegram long polling/webhook, лента реквизитов | низкая |
| 7 | Ревью и сдача | code-reviewer, security-reviewer, README, PR | низкая |

Сначала сквозной срез: этапы 1–4 в минимальном виде, затем углубление.

## Риски

| Риск | Митигирование |
|---|---|
| Ложные срабатывания на легальных конкурсах и рекламе | стоп-признаки, обязательные сочетания, allowlist брендов, контрольные примеры в синтетике, FPR в отчёте |
| Переобучение на синтетике | разбиение train/test по кампаниям, а не по сообщениям; правила работают без ML |
| OCR не читает кириллицу (PP-OCR ch-модель) | цифры, даты и латиница читаются; для кириллицы на скринах Claude vision при наличии ключа |
| Нет доступа к HF/Telegram из среды разработки | модели подключаемые, бот тестируется на уровне обработчиков |
| Масштаб 1 млн | numpy-индекс, нагрузочный тест в `scripts/loadtest.py` |

## Критерии готовности

- `pytest` зелёный, покрытие ядра ≥ 80%.
- `scripts/eval.py` выдаёт precision/recall/FPR по трекам на тестовом сплите.
- `scripts/seed_demo.py` + `uvicorn` показывают демо: один скриншот выплаты → таймлайн появлений с подсвеченной правкой; один номер Kaspi связывает три трека.
